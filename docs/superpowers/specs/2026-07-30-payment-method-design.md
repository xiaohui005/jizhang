# 支付方式功能设计

## 背景
当前账单只有收支类型、分类、金额、备注等信息，无法区分一笔钱是通过微信、支付宝还是银行卡完成。用户希望在支出和收入里都记录支付方式，并且在之后可以修改旧账、筛选和统计。

## 目标
- 账单新增时可选择支付方式。
- 账单编辑时可修改支付方式。
- 支出和收入都支持支付方式。
- 默认记住上次选择。
- 历史账单统一回填为 `微信`。
- 列表、筛选、统计都能按支付方式使用这个字段。

## 非目标
- 不新增独立的支付方式管理页。
- 不做多层级账户体系。
- 不做云同步或跨设备共享。

## 交互设计
### 新增账单
- 仍然从现有“+”入口进入。
- 使用底部弹层录入。
- 表单包含：收支类型、金额、分类、日期、备注、支付方式。
- 支付方式使用三选一：`微信`、`支付宝`、`银行卡`。
- 进入录入时默认预选最近一次使用的支付方式。

### 编辑账单
- 账单详情或长按菜单进入编辑。
- 编辑页复用新增页。
- 打开时回填该账单当前的支付方式。
- 保存时更新整条账单记录。

### 展示与筛选
- 账单列表和详情显示支付方式。
- 筛选条件增加支付方式维度。
- 统计页支持按支付方式汇总支出和收入。

## 数据设计
### 新字段
- 在 `BillItem` 中增加 `paymentMethod` 字段。
- 字段值固定为：`wechat`、`alipay`、`bank`。
- 显示文案映射为：`微信`、`支付宝`、`银行卡`。

### 默认值
- 新增账单默认使用最近一次选择。
- 如果没有历史选择，则默认 `wechat`。
- 旧账回填统一写入 `wechat`。

### 存储与迁移
- 数据库 `bills` 表增加 `payment_method` 列。
- 升级时迁移已有账单，把空值或旧数据统一补成 `wechat`。
- 导出 JSON 增加该字段。
- 导入 JSON 时兼容没有该字段的旧备份，并默认补成 `wechat`。

## 统计规则
- 支出统计按收支类型原有逻辑计算，再可按支付方式拆分。
- 收入统计同理。
- 支付方式只是账单的一个维度，不改变账单金额和类别含义。

## 错误与兼容
- 旧版本数据没有支付方式字段时，不报错，统一按 `wechat` 处理。
- 编辑旧账时可直接改成其他支付方式。
- 如果未来扩展更多支付方式，当前实现应保留向后兼容的字符串字段方案。

## 验收标准
- 新增支出和收入时可以选择支付方式。
- 新增时默认带出上次选择。
- 编辑旧账可以修改支付方式。
- 老数据显示为微信，不丢失现有账单。
- 导入导出 JSON 能保留支付方式。
- 筛选和统计能按支付方式工作。
